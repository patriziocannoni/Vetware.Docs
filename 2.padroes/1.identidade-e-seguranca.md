# Padrão de Identidade e Segurança

## Responsabilidades

Vetware.Auth emite JWT.
Vetware.Backend atua somente como resource server.
Perfis iniciais: proprietário, administrador, veterinário, atendente e tutor.
A autorização fina por papel não está definida.

## Contrato do token

- Algoritmo: HS256.
- Chave compartilhada: `spring.jwt.key`.
- Issuer obrigatório: `Vetware.Auth`.
- Claims obrigatórios: `iss`, `iat` e `exp`.
- Claims atuais: `sub` e lista `scope`.
- Audience não é validado porque o token não contém `aud`.

## Regras do Backend

- Validar assinatura, issuer e expiração.
- Usar `NimbusJwtDecoder` com secret HMAC e `MacAlgorithm.HS256`.
- Usar `JwtValidators.createDefaultWithIssuer("Vetware.Auth")`.
- Configurar sessão `STATELESS` e CSRF desabilitado para API REST.
- Exigir autenticação em toda rota de negócio.
- Liberar somente bypasses declarados, como health, Swagger e api-docs.
- Não implementar JwtEncoder, JWKS, RSA/EC, OIDC discovery ou Keycloak.

## CORS

As origens permitidas pertencem ao YAML do profile ativo.
A configuração global deve permitir `Authorization`, OPTIONS e os métodos HTTP usados.
O preflight OPTIONS não exige JWT.

## Resultado

Token ausente, malformado, expirado, adulterado ou com issuer diferente retorna HTTP 401.
Token válido permite o processamento pelo controller.
