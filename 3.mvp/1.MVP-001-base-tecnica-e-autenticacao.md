# MVP-001 — Base Técnica e Autenticação

## Objetivo

Proteger os endpoints de negócio do Vetware.Backend por JWT emitido pelo Vetware.Auth.

## Escopo

- Configurar o Backend como OAuth 2.0 Resource Server.
- Validar JWT HS256, assinatura, issuer, `iat` e `exp`.
- Exigir Bearer JWT em rotas de negócio.
- Configurar CORS por profile.
- Manter bypasses públicos explícitos.

## Excluído

Login, emissão de token, persistência de credenciais, JwtEncoder, JWKS, chave assimétrica, OIDC discovery, Keycloak, autorização fina por papel e interceptor HTTP do Frontend.

## Backend

- Manter `spring-boot-starter-security` e adicionar `spring-boot-starter-oauth2-resource-server`.
- Remover `spring-boot-starter-oauth2-authorization-server` do Backend, se presente.
- Criar `JwtConfig` em `br.com.vetware.backend.config`.
- Usar `NimbusJwtDecoder.withSecretKey(...)`, `HmacSHA256`, `MacAlgorithm.HS256` e `JwtValidators.createDefaultWithIssuer("Vetware.Auth")`.
- Configurar `SecurityFilterChain` com CSRF desabilitado, sessão `STATELESS`, resource server JWT e `anyRequest().authenticated()` após bypasses.

## Contrato

O Backend recebe `Authorization: Bearer <jwt>`. Sem header, token inválido, expirado, adulterado ou com issuer diferente retorna HTTP 401. OPTIONS permitido pelo CORS não exige JWT.

Vetware.Auth mantém `POST /vetware-auth/auth/token` com `application/x-www-form-urlencoded`; o campo de resposta atual é `acessToken`.

## Configuração

`spring.jwt.key` deve ter o mesmo valor no Auth e no Backend por ambiente. Origens CORS e bypasses pertencem ao YAML do profile ativo. Segredos de produção não podem ser versionados.

## Critérios de aceite

- JWT válido alcança o controller.
- JWT inválido retorna HTTP 401.
- Swagger, actuator e bypasses declarados não exigem token.
- Preflight CORS permitido não exige token.
- O Backend não emite JWT e não usa Keycloak ou JWKS.
